# plexus-early-window — Early Loading Window for Plexus Mod Loader

A module that displays an early loading window during game startup before the game window opens. It runs as a dedicated Java (Swing) process completely separated from the game process, presenting the loading screen without affecting the game runtime's graphics context or headless configuration.

## What This Module Does
- Spawns a separate, small Java (Swing) process at client boot to display an early loading screen until the game window draws its first loading frame.
- Applies across single and mixed execution environments for all loaders (Fabric, Quilt, Forge, NeoForge, and Plexus Mods).
- Does not share window libraries (GLFW in Minecraft 26.1 and 26.2, SDL in 26.3) with the game process.
- Operates independently without being affected by the `java.awt.headless=true` configuration set by Minecraft's `Main` entry point.
- Renders an appearance identical to the vanilla loading screen before the first frame:
  - Mojang red background (239, 50, 61), or a black background when the monochrome logo option is enabled.
  - Mojang Studios logo read directly from `assets/minecraft/textures/gui/title/mojangstudios.png` in the client jar.
  - Progress bar in the same position as the vanilla loading screen.
- Displays the same Plexus branding that `PlexusLoadingOverlay` in the game layer draws on the in-game screen:
  - Bottom right: Plexus logo (`plexus_cube.png`, 120 frames at 32 x 32, 60 ms per frame totaling 7.2 seconds per rotation) with three outer chevrons rotating around the central core without overlapping it, and the `Plexus Mod Loader` name.
  - Below the progress bar: loaded mod counts aggregated by loader (e.g., `Mods: Fabric 1 · Plexus 4`).
  - Bottom left: current task being performed by Plexus Mod Loader (e.g., `Found 5 mod files`, `Starting NeoForge`, `Starting Minecraft 26.2`).
- Uses `plexus_icon.png` (256 x 256, backgroundless logo; `EarlyWindowArt.icons()` downscales and provides all sizes from 16 to 256 used by Windows), identical to NeoForge icon art, as the window icon, with graphical assets generated by `tools/logo/LogoArt.java` matching `logo.svg` in the repository root and `tools/logo/logo-tile.svg`.
- Reads the game launch arguments `--width`/`--height` (defaults to 854 x 480) and `options.txt` (`guiScale`, `darkMojangStudiosBackground`) from `--gameDir` to match the game window size and center-screen position.
- Applies `-Dsun.java2d.uiScale=1` to match screen pixel sizes across Windows and Linux.
- Configured not to request keyboard focus, allowing the game window opening on top later to take focus naturally.
- Launches `javaw.exe` on Windows environments to prevent a separate console window from appearing, and limits the maximum heap to `-Xmx64m`.

## What It Owns
- `EarlyWindow`: Entry point on the game process side, responsible for process lifecycle management and command transmission (`start`, `show`, `status`, `progress`, `underBar`, `snapshot`, `close`).
- `EarlyWindowSettings`: Immutable record that parses window title, size, scale, background mode, and logo path from game launch arguments and `options.txt`. `letterColumns()` provides the number of characters that fit on a single line below the bar.
- `EarlyWindowMain`: Main class of the secondary JVM process, reading standard input and driving Swing components.
- `EarlyWindowProtocol`: Serializer and parser for the inter-process standard input-based command protocol (`show`, `status`, `progress`, `under`, `snapshot`, `close`).
- `LoadingScreenLayout`: Layout calculation class based on reverse-engineered metrics of `LoadingOverlay` and `Window.calculateScale` in Minecraft 26.1, 26.2, and 26.3.
- `LoadingScreenPainter`: Painter that renders the loading screen background, logo, bar, cube animation, and text. Draws the first line (mod count per loader) below the bar, and draws subsequent lines (unloaded mods) in amber between the logo and the bar directly above the bar (placing them below the bar would overlap with status text and lower-line names).
- `LoadingScreenState`: Record containing the name, status text, text below the bar, and progress (0–1) to display.
- `PixelLetters`: 5 x 7 pixel font renderer identical to `PlexusLoadingOverlay` in the game layer (renders uppercase English letters, digits, spaces, and `: · ' . , - _ / + ( )`).
- `EarlyWindowArt`: Utility that loads the logo frame sheet (`plexus_cube.png`), icon (`plexus_icon.png`), and the logo inside the client jar.

## What It Does Not Do
- Does not directly open a window inside the game process or control the game's graphics context (GLFW, SDL).
- Does not abort game execution if the window process fails to start or communication is lost (logs a single line and proceeds normally).
- Does not store copies of the Mojang Studios logo image in the repository (reads directly from the client jar).
- Does not collect or display FML internal progress messages from Forge and NeoForge.
- Does not display a window on macOS environments (not yet verified).
- Does not display a window in 1.21.11 experimental versions where the logo path is undefined, or on dedicated servers (DEDICATED_SERVER).
- Does not open a window in environments where the system property `-Dplexus.earlyWindow=off` is specified.

## Dependencies
- Uses only the `java.desktop` module from the standard JDK library.
- Has no compile-time dependencies on any other internal modules, external libraries, or game libraries.

## Key Entry Points
- `dev.plexusmodloader.earlywindow.EarlyWindow`: The sole public entry point for starting and controlling the window process from the game process side.
- `dev.plexusmodloader.earlywindow.EarlyWindowSettings`: Provides factory methods to build initial settings from game launch arguments and options files.
- `dev.plexusmodloader.earlywindow.EarlyWindowMain`: Main entry point executed in the secondary JVM process.

## Typical Flow
1. Upon client launch, `StartupWindow` in `plexus-runtime-impl` configures window settings via `EarlyWindowSettings.forGame` and calls `EarlyWindow.start` to launch the secondary process.
2. The secondary process (`EarlyWindowMain`) starts in a hidden state; once readiness is complete, the game process sends the `show` command to open the early window centered on screen.
3. When an FML host loader is detected, NeoForge starts in headless mode, and MinecraftForge disables its own early window via `ForgeEarlyWindowOff`.
4. While Plexus Mod Loader discovers mods, it sends commands such as `status("Found 5 mod files")` and `progress(0.15f)` to update progress and status.
5. Once mod resolution is complete, lines below the bar are passed via the `underBar` command. The first line is the mod count per loader, appending the count of nested mods contained within them after the count of mods placed directly in the mods folder (e.g., `Mods: Fabric 2 (+13 included)  ·  Plexus 4`). If any mod in the mods folder failed to load, starting from the second line it is shown in amber directly above the bar, such as `1 not loaded: sophisticatedbackpacks - see logs/latest.log` (as many names as fit, with the remainder as "and N more"). These lines are generated by `LoadingScreenModLines` in `plexus-version-adapter-api` and match the game layer loading screen.
6. When preparing the host loader, it transmits messages such as `status("Starting NeoForge")`, and upon executing Minecraft's `Main`, sends `status("Starting Minecraft 26.2")`; if a snapshot directory is specified, it saves `early-window.png` using the `snapshot` command.
7. When the game window opens (`opening()`, starting a 20-second safety timer) and `PlexusLoadingOverlay` in the game layer draws the first loading screen frame, `GameWindowListener.shown()` is called.
8. 0.3 seconds after `shown()` is called, it sends the `close` command or closes standard input to terminate the early window process and pass focus to the game window (automatically terminates if exceeding 3 minutes maximum).

## Known Limitations
- Because it is a secondary process rather than the game's own window, two windows exist concurrently for up to 0.3 seconds when the game window first opens.
- An additional secondary JVM process occupying up to 64 MiB of heap runs during early loading.
- macOS environments are not yet supported.
- Internal progress messages from Forge and NeoForge FML itself are not forwarded to the Plexus loading window.
- The progress bar follows Plexus Mod Loader's predefined phase progress rather than measured time.
- Standalone Quilt window behavior, macOS, Linux, launcher profile tests (`launcherProfileTest`), and the 1.21.11 experimental version have not yet been verified.
